# M-84 preregistration: the 4-seat independent gate on `gate4`

Date: 2026-10-10. Committed before any `gate4` run.

**Why this run exists.** M-67 through M-81 adopted a vector at every seat count on the belief that each seat count drew its own boards. The correction in [seat-count-programme.md](../../../.claude/specs/simulator/seat-count-programme.md) records that they did not: seat counts on one layout shared boards in every third-generation domain, so the five adoptions are not independent of each other. The fourth generation folds the seat count into the domain seed, so this run's boards and game seeds are shared with no other seat count and with no earlier run.

**Authorization, and the spend this run makes.** The closing report of the programme offered a fourth generation as the way to make the seat counts independent, and the user answered on 2026-10-10: "great do it. in the future dont ask about creating new generations/seeds. its cheap so just do it". `gate4` is a held-out domain, spent at most once per seat count, and this run is that one spend at 4 seats. **`gate4` is spent at 4 seats by this run whatever it reads.** `tuning4` and `eval4` are not touched by this programme.

**Change under test.** One arm, `simulator/placement/arms/sc_coverage_lo.json`, against the field's own weights: the live `simulator/placement/default-weights.json` with `coverageExponent` moved from 1.5 to 1.0 and nothing else moved, pinned to exactly that leaf by `the_sc_arm_files_are_the_committed_seat_count_perturbations`. It is the vector four seats ships today, adopted in M-69 after M-68 confirmed it.

**Design.** `evaluate`, `standard4`, 4 seats, **`--domain gate4`**, field `app_formula_draft:placement/default-weights.json@placement/default-weights.json`, every seat on `heuristic-v1-trader-aware-threat-devcards-denial` with `--player-trading`, `--threads 0`, 36000 boards x 2 reps, which is 288,000 paired units over 36,000 clusters, `--threshold 0.005`, `--alpha 0.05`, run from `simulator/`. Reference `base` is the field spec itself. The decision arm `candidate` carries the vector on the hero path with the opponent path pinned to the field's weights, exactly as on `gate3`. The power is twice the `gate3` run's, 36000 boards against 18000. `gate3` cleared the bar at four seats by 0.19pp, under the 0.25pp line this follow-on set for doubling, so at the old size a real effect of the size already read could miss on power alone. The size was fixed from third-generation readings, before any `gate4` run.

**Command.** The release binary is rebuilt first with `RUSTFLAGS="-D warnings"` in its own command block and must report `Finished` against a warm fingerprint. The five `gate4` invocations then run one after another from `simulator/`, in seat order 2, 3, 4, 5, 6, each alone on the machine's simulator workload, unpiped, with `uptime` recorded immediately before and after each, and none shares a shell command with a build or a test suite. This one is:

```text
target/release/unsettled-sim evaluate --layout standard4 --seats 4 --domain gate4 --field app_formula_draft:placement/default-weights.json@placement/default-weights.json --arm base=app_formula_draft:placement/default-weights.json@placement/default-weights.json --arm candidate=app_formula_draft:placement/arms/sc_coverage_lo.json@placement/default-weights.json --reference base --boards 36000 --reps 2 --policy heuristic-v1-trader-aware-threat-devcards-denial --threads 0 --player-trading --threshold 0.005 --alpha 0.05 --out runs/m84-seats4-gate4
```

**Decision rule (fixed before the run).** The user's rule for the programme, applied to the independent gate: a vector ships only on `better` at `--threshold 0.005`. Verdict `better`, the whole selected interval above `+0.005`, **keeps the adopted 4-seat vector**. **Any other outcome returns 4 seats to today's vector**, `worse`, `equivalent` or `inconclusive` regardless of point estimate: `SEAT_WEIGHT_OVERRIDES[4]` in `src/engine/weights.ts` is emptied, `simulator/tools/generate-placement-parity.ts` regenerates `simulator/placement/seat-weights/seats-4.json`, and the `SEAT_ADOPTIONS` row in `params_file.rs` moves with it. There is no partial outcome, no retry and no second `gate4` invocation at this seat count. No other seat count's result enters this decision, and `DEFAULT_WEIGHTS` does not move under either outcome.

**Admissibility and stop conditions.** The run must report domain `gate4` at seed `16013495161676280900`, which is `mix64(0x6a74_5eed_2026_1010 ^ 4)`. **Any illegal action stops 4 seats**, and so does a `base` win rate more than 3.29 binomial standard errors from `(1 - d) / 4`, `d` being its draw share; either way the domain is spent at this seat count, the independent gate has not confirmed the vector, and 4 seats returns to today's vector with the entry saying why. `simulator/runs/` is gitignored, so the M entry is the record.

**Prediction (recorded before the run).** A point estimate between `+0.6pp` and `+1.15pp`, centred near `+0.85pp`. The two held-out third-generation readings were `+0.977pp` and `+0.844pp`, each read only because the one before it passed, so I centre under their mean. `gate3` delivered a half-width of 0.153pp at 18000 boards, so I expect about `+/-0.11pp` here, which puts the `better` line near `+0.61pp`. I put `better` at about 96% and `inconclusive` at about 4%.

**Scope, and what the entry may not be cited for.** One contrast, one layout, one seat count, one policy, one domain, one spend. The arm moves the hero's weights alone against 3 seats on today's vector, so nothing here observes the world the adoption creates in the app, where every seat at 4 seats carries the vector. The greedy opponent model inside every hero was measured in M-61 at four seats on `standard4` only, so no verdict may be described as taken against a correctly specified model. The field is the same as on every third-generation domain, so this run controls for seeds and for the shared boards, and not for field-overfit. The vector was chosen on third-generation `tuning3` boards that other seat counts shared; this run does not re-screen, so it says whether that choice holds on independent boards and nothing about whether a different arm would have been chosen there.

**Numbering.** M-81 and the correction note after it are the last entries in `.claude/specs/simulator/measurements.md` at this commit. The five independent gates take M-82 to M-86 in seat order 2, 3, 4, 5, 6, so this run takes M-84.
