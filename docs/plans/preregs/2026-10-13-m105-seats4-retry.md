# M-105 preregistration: the 4-seat retry of the cut-off arms on `tuning4`

Date: 2026-10-13. Committed before the invocation executes.

**Why this run exists.** The 4-seat screen (M-100) read `flat_50` and `flat_75` as `inconclusive` with estimates at or above 0.0025, which requirement 29 of [cut-off-programme.md](../../../.claude/specs/simulator/cut-off-programme.md) answers with one retry at four times the screen's boards. `tuning4` is already spent at 4 seats; `eval4` and `gate5` are not touched here.

**Design.** The screen's own command with the arm list cut to `base` and `flat_50` and `flat_75`, at **22,000 boards** x 2 reps, four times the `B` the pilot fixed. Run from `simulator/` alone on the machine's simulator workload, with `uptime` recorded before and after.

**Command.**

```text
target/release/unsettled-sim evaluate --layout standard4 --seats 4 --domain tuning4 --field 'app_formula_draft:placement/seat-weights/seats-{seats}.json@placement/seat-weights/seats-{seats}.json' --arm 'base=app_formula_draft:placement/seat-weights/seats-{seats}.json@placement/seat-weights/seats-{seats}.json' --arm 'flat_50=app_formula_draft:placement/arms/co_flat_50_s{seats}.json@placement/seat-weights/seats-{seats}.json' --arm 'flat_75=app_formula_draft:placement/arms/co_flat_75_s{seats}.json@placement/seat-weights/seats-{seats}.json' --reference base --boards 22000 --reps 2 --policy heuristic-v1-trader-aware-threat-devcards-denial --threads 0 --player-trading --threshold 0.005 --alpha 0.05 --out runs/m105-seats4-retry
```

**Decision rule (fixed before the run).** After a retry `better` survives and anything else is dropped; there is no second retry. An arm's last reading is this one. Then requirements 30 and 31 apply as the screen's preregistration states them: a second-stage arm `flat_reprice` at 4 seats if some flat arm's last reading is positive and not `worse` (`reprice_only`'s already is: its screen estimate is positive and it read `equivalent`), built on the flat arm whose last-reading estimate is highest; and the candidate is the arm with the highest last-reading estimate among those that read `better`.

**Stop conditions.** `illegalActions` above 0, or a `base` arm that misses the symmetric corner: with `c = (1 - draws / games) / 4`, a miss is `abs(wins / games - c) > 3.29 * sqrt(c * (1 - c) / games)`. Either stops 4 seats at this run with both keys at 0.

**Prediction (recorded before the run).** The screen estimates were picked for being the largest, so I expect each to shrink on fresh game seeds over the same boards plus three times as many new ones. For `better` an arm needs its whole interval above +0.5pp, so an estimate near +0.75pp at this size. I put `better` for either arm at about 10% and expect both to end `inconclusive` or `equivalent` with estimates between 0 and +0.4pp.

**Scope.** One layout, one seat count, one policy, one field, the hero's formula alone. Nothing read here changes a command at another seat count.
