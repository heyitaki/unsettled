# M-74 preregistration: the 3-seat confirmation on `eval3`

Date: 2026-10-10. Committed before the run.

**Authorization, and the spend this run makes.** `eval3` is a held-out domain, spent at most once per seat count, and this run is that one spend at 3 seats. The user authorized it in advance on 2026-10-10, in the words [seat-count-programme.md](../../../.claude/specs/simulator/seat-count-programme.md) quotes under "Seed domains and the authorization": "Per seat count: screen on `tuning3`, confirm the survivor once on `eval3`, decide once on `gate3`. I pre-authorise those one-shot spends for each seat count." **`eval3` is spent at 3 seats by this run whatever it reads**, and after it no further `eval3` command may run on `standard4` at 3 seats. Board generation consumes layout and seat count, so the other seat counts' `eval3` boards are untouched.

**The condition that let this run be preregistered.** M-73 screened twelve arms at three seats on `tuning3` and left two surviving axes: `coverage_lo` read `better` at `+1.024pp` on the screen, and `diversity_hi` read `better` at `+0.683pp` on its retry over 252,000 paired units. The combine pass then read both removals `worse` against the combined vector, so neither axis was dropped, and read `base` `worse` against it at `-1.929pp` on `[-2.247pp, -1.611pp]`, which is the combined vector reading `better` against `base`. Had the screen left no survivor this preregistration would not exist and `eval3` would stay unspent at three seats.

**Change under test.** One arm, `simulator/placement/arms/sc_s2_combined.json`, against the field's own weights. It is the live `simulator/placement/default-weights.json` with `coverageExponent` moved from 1.5 to 1.0 and `diversityWeight` moved from 1.6 to 3.2 and nothing else moved, pinned to exactly those two leaves by the `SC_COMBINED` table in `the_sc_arm_files_are_the_committed_seat_count_perturbations`. The file was minted for two seats; three seats' survivors are the same two values, so it is read here under its existing name. It is also the vector M-72 adopted at two seats, which has no bearing on this run: the boards, the seat count and the trading rule all differ.

**Design.** `evaluate`, `standard4`, 3 seats, **`--domain eval3`**, field `app_formula_draft:placement/default-weights.json@placement/default-weights.json`, every seat on `heuristic-v1-trader-aware-threat-devcards-denial` with `--player-trading`, `--threads 0`, 42000 boards x 2 reps, which is 252,000 paired units over 42,000 clusters, `--threshold 0.005`, `--alpha 0.05`, run from `simulator/`. Reference `base` is the field spec itself. The decision arm `candidate` carries the candidate on the hero path with the opponent path pinned to the field's weights. The power is `4B`, four times the screen's boards, as the programme file fixed before any run.

**Command.** The release binary is rebuilt first with `RUSTFLAGS="-D warnings"` in its own command block and must report `Finished` against a warm fingerprint. Then the single invocation, from `simulator/`, with `uptime` recorded immediately before and after:

```text
target/release/unsettled-sim evaluate --layout standard4 --seats 3 --domain eval3 --field app_formula_draft:placement/default-weights.json@placement/default-weights.json --arm base=app_formula_draft:placement/default-weights.json@placement/default-weights.json --arm candidate=app_formula_draft:placement/arms/sc_s2_combined.json@placement/default-weights.json --reference base --boards 42000 --reps 2 --policy heuristic-v1-trader-aware-threat-devcards-denial --threads 0 --player-trading --threshold 0.005 --alpha 0.05 --out runs/m74-seats3-eval3
```

**Decision rule (fixed before the run).** Verdict `better`, the whole selected interval above `+0.005`, confirms the candidate and sends it to the gate on `gate3`, which gets its own preregistration. **Any other outcome stops 3 seats on today's vector**, `worse`, `equivalent` or `inconclusive` regardless of point estimate, and `gate3` is then never run at 3 seats. There is no retry and no second `eval3` invocation at this seat count.

**Admissibility and stop conditions.** The invocation runs alone in its command block, unpiped. It must report domain `eval3` at seed `16691289016504815632`, the decimal form of `0xe7a3_5eed_2026_1010`. **Any illegal action stops 3 seats**, and so does a `base` win rate more than 3.29 binomial standard errors from `(1 - d) / 3`, `d` being its draw share; either way the domain is spent at this seat count and today's vector stays. `simulator/runs/` is gitignored, so the M entry is the record.

**Prediction (recorded before the run).** A point estimate between `+1.2pp` and `+2.2pp`, centred near `+1.7pp`. The combine pass read `+1.929pp` on seeds both axes were selected on, and the diversity half of it cleared the bar on its retry by only 0.04pp, so I expect a few tenths of shrinkage here, more than two seats showed. The combine pass delivered a half-width of 0.318pp at 10500 boards, so I expect about `+/-0.16pp`, which puts the `better` line near `+0.66pp`. I put `better` at about 97% and `inconclusive` at about 3%.

**Scope, and what the entry may not be cited for.** One contrast, one layout, one seat count, one policy, one domain, one spend. The arm moves the hero's weights alone against 2 seats on today's vector, so nothing here observes the world an adoption creates, where every seat at 3 seats carries the candidate. The greedy opponent model inside every hero was measured in M-61 at four seats only and found misspecified against a draft-aware field, so no verdict may be described as taken against a correctly specified model. The field is the same on `tuning3`, `eval3` and `gate3`, so a held-out domain controls for seeds and not for field-overfit.

**Numbering.** M-73 is the last entry in `.claude/specs/simulator/measurements.md` at this commit, so this run takes M-74.
