# M-59 preregistration: SP5 setup draft awareness

Date: 2026-09-02. Committed before the run.

**Change under test.** `PlacementKind::AppFormulaDraft`, added by Task 20 of `docs/plans/simulator-placement-sp3-sp5.md` and implemented in `simulator/crates/engine/src/placement/draft.rs`. The field's setup path is greedy twice: `simulator/crates/engine/src/placement/mod.rs::choose_app_formula` takes the argmax of the formula for the pick in front of it and knows nothing about the picks that follow. The draft kind replaces the first settlement with an exact lookahead. For each legal candidate `c` it places `c`, replays every seat that picks between the hero's two settlements at that seat's own argmax under the opponent weights, and ranks `c` by `marginal(c)` plus the best second settlement still legal once those rivals have picked, with the setup grant on for the second. A candidate with no surviving second site scores `marginal(c)` alone. The second settlement stays the plain argmax, because nothing the hero cares about follows it. Both picks take the setup road by SP3's road rule at the hero weights, which at `expansionWeight` 0 falls through to the same far-endpoint scoring the field uses. The kind never prunes: it scores every legal candidate and every intervening pick, and its speed comes from `draft.rs::ScoreRows`, a cache keyed by seat, holdings and grant, which identifies a score exactly while no component reads the occupancy and is therefore kept only when both formulas carry `expansionWeight` 0.

**This is the gap-closing half of SP5.** `SIM-GAP-20` in `.claude/specs/simulator/gaps.md` says the placement heuristics read `vertex_owner` for legality alone, with no draft-order awareness and no model of what an opponent takes next, so setup is the one phase of the game the opponent model does not reach. `.claude/specs/simulator/placement-programme.md` assigns closing it to SP5 and states that the opponent-model half is never cuttable, because closing the gap is the phase's point. The gap closes when the kind lands and this entry is recorded, whatever this entry reads. What is being measured here is therefore not whether to keep the kind but how much the missing lookahead was costing.

**The arm, and why there is exactly one.** One decision arm, `draft` = `app_formula_draft:placement/default-weights.json@placement/default-weights.json`, registered as `app_formula_draft:default-weights@default-weights` by `simulator/crates/cli/src/heuristics.rs::parse_heuristic`. Hero weights and opponent weights are both the shipped `simulator/placement/default-weights.json`, so the only thing that differs between the arm and the reference is the lookahead itself: the same weights file on both sides, the same components, the same road rule, the same legality. Reference `base` = `app_formula:placement/default-weights.json`, the shipped vector under the shipped greedy kind. No weights file is added by this run and no arm file exists for it, because the arm is a placement kind rather than a parameter vector. A second arm would have to move a weight as well as the kind and would confound the two.

**Why the opponent path is pinned to the field's weights.** The spec string takes two paths so a later sweep can move the hero's formula while the model it replays the rest of the field with stays fixed. In this run both halves are the same file, which makes the opponent model **correctly specified by construction**: the three rival seats are running exactly the formula the lookahead assumes they are running. That is a deliberate best case and it bounds what the entry can claim. It measures what draft awareness is worth against a field the model predicts exactly, not what it is worth against a field that plays differently, and no later phase may cite it as the latter.

**The exactness condition, and the second difference this design cannot separate.** `simulator/crates/cli/tests/draft_lookahead.rs::the_lookahead_predicts_the_picks_the_field_actually_made` holds the model against ten traced `tuning` games at all four hero seats and requires the predicted intervening picks to equal the picks the field made. It holds only on tie-free games, and the test screens for them by re-scoring every legal candidate at every pick, because the field breaks a settlement tie with a draw from its own policy stream while the lookahead takes the lowest vertex index. So the arm differs from the reference in two ways, not one: the lookahead, and deterministic tie-breaking in both the settlement argmax and the setup road. **The two are not separable in this design and no attempt is made to separate them.** How often the second one fires is not pinned anywhere: the committed test constants establish only that at least ten of the first sixty `tuning` boards are tie-free, which is enough to say ties are not rare and not enough to bound their rate from above. Two consequences are stated now rather than after the reading. The tie-break difference is a coin flip against a coin flip on states where the formula is indifferent, so it should not bias the estimate in either direction, but it adds units where the two games diverge for no reason of substance, which inflates the discordant count and therefore the interval. And because the draft kind draws nothing from the RNG while the field draws on every tie, the hero seat's own policy stream is offset for the rest of any game containing a setup tie, so that game's later random tie-breaks differ too. `simulator/crates/engine/src/rng.rs::Streams` gives each seat its own policy generator and keeps the dice, the deck, the chance draws and the trade draws in four separate ones, and `game.rs::setup_pick` hands `choose` only the picking seat's policy stream, so the offset reaches the hero's own later draws and nothing else: the board and the dice stream are identical between arm and reference on every unit.

**Why this field.** A placement kind has to be scored against the live placement, so the field is `app_formula:placement/default-weights.json` and the reference is the same spec, per the plan's protocol and following M-51 through M-54, M-57 and M-58. Every seat runs the post-SP1 composite `heuristic-v1-trader-aware-threat-devcards-denial` with player trading; `simulator/crates/cli/src/evaluate.rs` gives the arm to the hero seat alone, so the hero drafts with a lookahead against three seats that draft greedily. That asymmetry is the measurement: a field where every seat looked ahead would have each seat's model predicting three other lookaheads it does not implement, which is a different and much larger question this run does not ask.

**Design.** `evaluate`, `standard4`, 4 seats, `--domain tuning`, 2000 boards x 2 reps, which is 16,000 paired units over 2000 clusters, `--threads 0`, `--threshold 0.01`, `--alpha 0.05`, reference `base`, both specs in one invocation, 32,000 games. That is the plan's screen power for an optional term, matching M-38's placement screens, M-49, M-52, M-53, M-54's screen, M-57 and M-58, and it is used here for a gap fix so the reading is comparable with the term readings around it.

**Power.** At this power the pooled rows of M-54 came back with half-widths of `+/-0.71pp` and `+/-0.78pp`, M-57's with `+/-0.35pp` and M-58's with `+/-0.47pp` and `+/-0.50pp`, the width tracking how many units each change made discordant. This arm should be the most discordant instrument the plan has run, so the interval should sit at the wide end of that range, near `+/-0.8pp`. A pooled effect at or above 1pp is resolvable; a few tenths of a point is at the edge. The per-hero-seat table from Task 1 is the reading of record for how the effect splits by slot and carries no verdict, and at these half-widths a per-slot row establishes a direction at best.

**Why the per-slot split is the interesting part.** The number of picks the lookahead has to replay is set by the slot and by nothing else: six intervening picks at slot 0, four at slot 1, two at slot 2, none at slot 3. Those are two different mechanisms wearing one name. At slot 3 the lookahead replays nothing and is exact pair optimization, the joint best pair against greedy-then-greedy on an almost-full board. At slot 0 it is a six-pick prediction on an empty board, where the greedy first pick is choosing a vertex whose complement three rivals will strip before the hero picks again. Both are cases the field cannot price and neither is the other.

**Timing, preregistered before the run.** Task 20 timed a 200-board `evaluate` at `--reps 2` and `--threads 1` carrying one draft arm: 1600 games in 3.70 seconds, or 432.4 games per second on a single worker. This screen is 32,000 games, of which 16,000 carry the draft hero and 16,000 carry the reference. Taking the deliberately pessimistic floor, that the draft half gets no parallel speedup at all, the draft half takes 37.0 seconds and the base half takes 2.1 seconds at M-58's measured 7,465.3 games per second, for a ceiling near 39 seconds; at 18 workers it should land in single-digit seconds. **The run is predicted well under the plan's five-minute and eight-minute marks, so it runs in the foreground.** The retry, if bought, is four times the boards and 128,000 games, whose ceiling under the same pessimistic floor is about 156 seconds, also under five minutes and also in the foreground. One trigger is fixed now so the contingency is not decided after seeing the clock: **if the screen's observed elapsed time exceeds 60 seconds**, which is more than 1.5 times the zero-parallelism ceiling and would mean the extrapolation is wrong, the retry is launched in the background with `&` and polled by a loop that prints the elapsed minute while the process lives, per the plan's long-run rule, and the artifact is read afterwards. No invocation is piped through `tail` or `head` in any branch.

**Decision rule (fixed before the run).** This is gap-closing work and **the kind lands whatever the reading is**, per the plan's gap-fix rule and `placement-programme.md`'s statement that the standing disposition rule governs optional terms and not the gap-closing work in SP1 and SP5. `better` records the lookahead as positive and as an SP6 candidate for the field placement, which is SP6's decision and not this run's. `equivalent` at this declared power records that greedy setup was costing nothing measurable against a field it predicts exactly, and the kind stays. `worse` records the loss, quantifies it, **flags it for the user**, and reverts nothing. `inconclusive` buys units exactly once at four times the boards with `--reps` unchanged, in the retry invocation above, and a second `inconclusive` records the effect unresolved and stops. In every branch `SIM-GAP-20` is deleted from `.claude/specs/simulator/gaps.md`, because the gap is that the setup path has no opponent model and it now has one; the sentence in `.claude/specs/simulator/programme.md` that names `SIM-GAP-20` moves with it. `SIM-GAP-34` does not move: a term at weight 0 closes nothing, and nothing in this run adopts anything. Record only on every default: no shipped value moves, in `src/engine/weights.ts`, `simulator/placement/default-weights.json`, `simulator/placement/phase-i-candidate-weights.json` or anywhere else, and the field's placement stays `app_formula:placement/default-weights.json` throughout, since making the draft kind the field is an SP6 decision the plan puts out of scope.

**Prediction (recorded before the run).** I predict **`draft` reads positive**, with a pooled point estimate between `+1.0pp` and `+2.5pp`, most likely `better` and otherwise `inconclusive` against the `+/-1pp` threshold, on **4,000 to 6,000 discordant units of 16,000**. The direction argument is that the field's first pick is greedy over a quantity that is not what it wants: it maximizes the value of one settlement when the thing that decides the game is the pair, and the whole surviving-pair value is unpriced. That should be worth more than any single weight in the formula, because it is a change of objective rather than a change of coefficient, and it is the largest structural change the plan makes. The magnitude bracket is set off M-54, the only prior reading of a genuinely new input, which delivered `+1.13pp` at its best arm on the retry; a change of objective should beat a term added to the objective, but not by an order of magnitude, because greedy and joint agree on most boards.

The discordant bracket is arithmetic rather than analogy, which is the correction M-58's entry says it should have made and did not. A unit is discordant only if the two games end differently, so the count is roughly `0.375 * 16,000 * (share of units where the two games diverge at all)`, the 0.375 being `2 * 0.25 * 0.75` for a re-randomized game at four seats. M-58's 1,450 implies divergence on about a quarter of its units and M-54's 3,697 implies about six tenths. This arm should diverge on nearly every unit, because it changes the first pick whenever greedy and joint disagree and changes something whenever a tie fires even when they agree, so 70 to 100 percent divergence puts the count at 4,200 to 6,000. If the count comes in near M-58's, the lookahead is agreeing with greedy far more often than this argument allows and that is the finding, whatever the estimate says.

Per slot, I predict **positive at every slot with the largest reading at slot 0**, between `+2pp` and `+5pp`, on the argument that slot 0 is where the greedy first pick is most wrong: six picks intervene, the hero's favourite region is stripped before it picks again, and the lookahead is the only thing in either scorer that knows this. I expect slot 3 positive but smallest, since there the lookahead is a pair optimization over an almost-full board where few pairs are still available to differ over. Two readings would change my mind and are named now so they cannot be explained away later. **A negative pooled estimate** would say that greedy-then-greedy is accidentally better than joint optimization against this field, which would most likely mean the formula's own second-pick marginal is a poor estimate of a second settlement's worth, so optimizing the pair against it optimizes the wrong thing harder; that is a finding about the formula, not about the lookahead, and it is the case that gets flagged. **Slot 3 clearly ahead of slot 0** would say the gain is pair optimization and not opponent modelling at all, which would mean the model's six-pick replay buys nothing over its zero-pick case and that `SIM-GAP-20` was the smaller half of what SP5 fixed.

**Threshold and alpha.** `+/-1pp` practical threshold, alpha 0.05. Interval selection is the harness's own rule in `evaluate.rs::try_paired_stats`, the wider of the McNemar and board-clustered intervals.

**Admissibility.** The release binary is built before the measurement starts and the build is confirmed to report `Finished` against a warm fingerprint, which is M-50's lesson and the plan's explicit rule that a build must not land inside the timed window. `uptime` is recorded immediately before and immediately after each `evaluate` invocation and both readings enter the M entry, along with the games per second, which Task 22 requires in the provenance because this is the first kind in the plan whose cost is not arithmetic on precomputed vertex data. No invocation shares its command block with a build, a test suite or any other CPU-heavy job. Zero illegal actions required. Timing is a throughput observation only; the outcomes are deterministic in the seeds and unaffected by load. The reference arm's win rate is checked against the symmetric 0.25 corner, as M-51 through M-54, M-57 and M-58 checked theirs, and it is expected to reproduce M-58's `base` figure of 3,988 of 16,000 to the game: the domain seed is unchanged, the reference spec is unchanged, and the placement code has moved since M-58 only by branches that the new kind alone reaches, so any drift shows up in the reference's own win rate. **That reproduction is a registered check and a mismatch makes the run inadmissible**, since it would mean the new kind touched the shipped path. `simulator/runs/` is gitignored, so the artifacts stay out of the tree and the M entry is the record.
