# CLAUDE.md

Guidance for Claude Code in this repository.

## What this is

Unsettled: an offline, browser-only Catan starting-position analyzer (React 19 + TS + Vite). No backend: all state lives in `localStorage`. Phase 1 (board editor + screenshot import) and Phase 2 (rank the best placements for your picks in a snake draft, accounting for intermediate picks) are done. Once a draft is finished the same panel becomes the move adviser (Best moves), which tracks turns and ranks every in-game decision with the Rust turn policy compiled to WebAssembly. Phase 3 (boons/curses expansion scoring) is paused: do not start it before the user supplies the full boon/curse list. See the `catan-companion-roadmap` project memory note, which lives outside the repo.

## Commands

- `npm run dev`: Vite dev server
- `npm test`: unit tests, then `src/engine/__tests__/perf.test.ts` on its own so the performance guard never measures test-runner contention, then `src/engine/advice/__tests__/advicePerf.test.ts` on its own for the same reason. Watch: `npx vitest`. One file: `npx vitest run src/model/__tests__/board.test.ts`. By name: `npx vitest run -t "substring"`
- `npm run test:e2e`: Playwright specs in `e2e/`, on their own dev server at port 5199. Specs import app modules (`tsconfig.e2e.json` resolves like the app), so pin an assertion to the constant it checks. `e2e/seed.ts` seeds an unclaimed roster: a fresh board boots with one player already claimed, so any test of the claim row seeds the stored workspace and reloads. Phone tests use the `test.use` block at the top of `phoneShell.spec.ts`; never spread a `devices[...]` preset, which selects WebKit (not installed). The board's placement dots take no pointer events, so click one by coordinates or with `{ force: true }`. Screenshots land in `test-results/phone/`. To check a regression test really bites, point it at a worktree of an older commit: `UNSETTLED_E2E_PORT=5201 UNSETTLED_E2E_ROOT=<worktree> npm run test:e2e`
- `npm run test:pwa`: production-build Playwright checks in `e2e/production/` on port 5200 (`npm run build` first). Artifacts go under `test-results/production/`.
- `npm run typecheck`: `tsc -b` (strict; no `any`)
- `npm run lint`: `oxlint`
- `npm run build`: typecheck + Vite build. Needs no Rust toolchain: the advice engine is the committed `src/engine/advice/engine.wasm`.
- `simulator/tools/build-wasm.sh`: rebuilds that file and `engine.wasm.src-hash` (needs the `wasm32-unknown-unknown` target). `--check` verifies the source hash and the binary's checksum without Rust, and is what CI runs.

## Architecture

Data flows from `parser/` to `model/Board`, then to `engine/` and `ui/store`, then to `persistence/`. The `Board` interface (`model/types.ts`) is the single source of truth passed between all layers. A `Game` (`model/game.ts`) wraps a `Board` with the per-player state that cannot be derived from the pieces (hands, dev cards, knights, VP cards, award holders, and after the draft `turn` and the claimed player's `devHand` by type); tabs, the library, and import/export all persist whole games; storage shapes older than the `Game` envelope are no longer read.

- **`model/`**: pure geometry + board logic, no React. `coords.ts` is the foundation: axial `{q,r}` hex coords; `VertexId`/`EdgeId` are deterministic strings built from **sorted** member coords (`v:q,r;q,r;q,r`), so any corner/edge has one canonical id regardless of which hex references it. `layouts.ts` defines the `standard4`/`extension6` grids and default port edges. `serialization.ts` validates untrusted board JSON with exact-key structural checks; `board.ts` builds/validates boards. `Game.awards` records the Longest Road and Largest Army holders: a qualifying incumbent keeps a tie, an imported tie stays unknown until corrected through `AwardControls`, and games saved before the field still load. `turn.ts` holds one pure function per recorded in-game action, each returning the next `Game`. `Game.turn.playerId` is whose turn it is and whose advice is shown; `board.mePlayerId` means only "the player whose cards are known exactly". A rival's hand is a known lower bound per resource plus `handUnknown` cards nobody saw. The typed `devHand` is dropped whenever it would exceed the player's public dev card count.
- **`engine/`**: pure placement analysis, no React: draft-state inference from building counts, legality, weighted valuation with per-factor breakdowns, seeded opponent rollouts (`analyzeBoard`), whose modal pre-window (the `Likely gone` line) takes each picker's top recommendation from a nested analysis, so it matches the list that player is shown and costs one extra full ranking per pick ahead of the ranked one. `targetPick` ranks a later pick of the analysed player, whose own earlier pick then joins the pre-window; the worker caches the nested rankings by board content and picker. Sampled pre-windows draw from that picker's same ranked list while they follow the modal line; once they leave it, and in all mid-windows, picks come from `opponentPick`, which prices a rival's first settlement as a pair from a per-analysis partner table and takes the half worth more alone first. Scoring also takes the board's occupancy (blocked vertices plus road owners, for `expansion.ts`'s walk) and the picking seat's draft slot. Phase 3 boons/curses have no hook yet; add one when the list arrives rather than carrying an empty plumbing layer. The UI runs `analyzeBoard` only in `analysis.worker.ts`, never during render: `AnalysisProvider` shares one worker result across the active board's panels and marks, and `analysisClient` cancels obsolete jobs and keeps the last `ANALYSIS_CACHE_SIZE` results in an LRU keyed by board content and target pick, which a production build also saves to `localStorage` (`ANALYSIS_CACHE_KEY`) and drops whenever its bundle hash changes. `DraftGrid`, `DraftRibbon` and roster labels use cheap draft inference without rollouts. Four- and six-seat analysis are both expensive, so do not add work per rollout scan casually. `engine/advice/` is the post-draft adviser's client side: `protocol.ts` types the JSON that `simulator/crates/engine/src/advice.rs` reads and writes, `wasm.ts` calls the committed `engine.wasm` through three raw exports (`alloc`, `dealloc`, `advise`; no `wasm-bindgen`), and `advice.worker.ts` is the only place it runs. Settlement picks stay on the TypeScript engine.
- **`parser/`**: offline screenshot to `Game`. `parseScreenshot` (`index.ts`) calls the Settled steps directly: `registration` fits the hex grid and bounds the board, then `tiles`/`tokens`/`ports`/`pieces` read its content over one `components.ts` labeler. `sources/settled/` supplies the palette and player-pill reader. Pills give turn order, colour names, hand counts and the highlighted player to claim; VP is cross-checked against parsed buildings and possible public awards. Settlement badges order each player's picks before buildings are emitted in snake order. Synchronous parsing is pure pixel analysis and emits `ParseIssue[]` rather than throwing. Screenshots with no pills synthesize players from piece colours.
- **`ui/`**: `store.ts` is a `useReducer` context holding multiple `TabState`s (each an independent game with its own `past`/`future` undo stacks over whole `Game`s) plus the active `Tool`. Board edits dispatch `commit` with the next `Board` and the reducer wraps it via `withBoard`; stat edits dispatch `commit-game`. Wider than 760px `App` mounts the desktop `Workspace`; at phone widths (`max-width: 760px`, any orientation) it mounts `phone/PhoneShell` instead, gated by `usePhone`. The two trees share `AnalysisPanel` and `DraftRibbon` outright, and the Library and roster logic through hooks (`useLibrary`, `useRenameTab`, `useJsonFiles`, `useRowReorder`). Best picks views a pick independently of the claim: the store's `viewedPick` is a draft slot of any player (null means the claimed player's next pick), set from the ribbon or the context line's menu and cleared when the board or the claim changes under it. `AnalysisProvider` analyses the board as the viewed player (`viewedPlayerId` in `draftSlots.ts`), and the cards, marks and `Place settlement` follow that player, while Players, the phone header dots, Best moves and the piece brush follow the claim. The Best picks step buttons (`useDraftSteps`) commit each step as an ordinary edit and keep their forward list in the hook, outside the store's undo stacks. When the draft is complete `AnalysisPanel` renders `BestMovesPanel` instead, in both trees: turn order circles pick the active player, trays record what happened, and ranked moves follow the Best picks select, pin and hover rules plus `Apply`, one undoable commit including the hand change. `AdviceProvider` and `adviceClient` mirror the analysis pair. A tray that needs a spot on the board sets the store's `pick`, and while it is set `BoardCanvas` routes clicks to it instead of the active tool; `placementSlots.ts` holds their shared slot rules, nearest-target lookup and building cycle. The one `pieces` tool acts on the nearest actionable corner or edge within half a hex edge (29 board units): a corner cycles empty, settlement, city, empty, and a road toggles. A click within 10 board units of the previous click stays on that click's target, or does nothing if that target is no longer actionable; a click on another target's dot, or within 8 units of another target, acts on that target instead. While the draft is in progress, a settlement cycles straight to empty. A tapped piece keeps its owner, and the brush player colours only new pieces; with no brush player, only existing pieces are actionable. Super city joins the cycle after city only on a board that already has one, and a super city always cycles to empty. Board picks use the same reach over their legal corners or edges. The import dialog is the panel's sibling so it survives the swap. A screenshot whose terrain (`terrainKey`: layout, tiles, number tokens, ports) equals a library map's, or an unsaved open board's, asks whether to update it (`matchingBoard`); the update is `mergeScreenshot`, one commit on that board's own tab, and the parse result's `read` tells it what the pills supplied (a roster at all, and whose hand size) so an unread value never overwrites a saved one. `glyphs.tsx` is the one home for inline SVG icons (one flat family on a 20-unit grid; the board draws its own piece shapes). Boards are switched from the Library; neither tree has tabs, an import panel or a footer. The workspace tree is built to [`.claude/specs/desktop/spec.md`](.claude/specs/desktop/spec.md) and the phone shell to [`.claude/specs/mobile/spec.md`](.claude/specs/mobile/spec.md), so read both before touching `src/ui/phone/`, a promoted base rule or the `max-width: 760px` arm of `editor.css`. Modals mount through `ModalDialog`, a native `<dialog>` that makes the rest of the page inert, closes on Escape and hands focus back to its opener, so never hand-roll a focus trap. `ContextMenu` is a native popover anchored in CSS rather than positioned from JS.
- **`persistence/`**: `localStorage.ts` saves the whole workspace (`WORKSPACE_KEY`) and named maps (`MAPS_KEY`), and corrupt blobs are preserved under `*.corrupt` keys instead of being discarded. Boards autosave into the library (`ui/libraryAutosave.ts`, 500ms debounce, and an unlinked tab links to a new map on its first non-blank edit), so there is no save button, dirty marker or close prompt anywhere. `isFreshGame` (`model/serialization.ts`) is the one rule for "nothing beyond a fresh board of its layout", shared by the autosave and the backup. The library keeps `MAX_MAPS` (50) entries: a new map beyond that evicts the least recently touched ones, and the autosave closes any tab linked to an evicted map so it cannot re-save itself past the cap. `backup.ts` exports the library plus open games and preserved corrupt blobs. Restore validates every entry before one write, merges without overwriting, and tests the cap after the merge rather than against the file's own length.
- **`simulator/`**: separate Rust workspace (outside the Vite build and `npm test`) that self-plays games to measure which starting placements win. Never hand-edit `simulator/topology/*.json`. Change the placement scorer or the analysis and you must regenerate `simulator/fixtures/analysis-parity.json` (`cargo test --release -p unsettled-engine --test analysis_parity regenerate -- --ignored`) and re-verify its diff by hand; `analysis_parity.rs` checks it natively and `wasmAnalysisParity.test.ts` checks the committed wasm against it. `crates/engine/src/advice.rs` is the adviser's bridge: it builds a policy view from the app's game JSON and returns advice with a one-line reason from the scorer's own terms, never changing a score; `crates/wasm` exports it. Change a scorer, a policy or the rules and `simulator/fixtures/bench-hashes.json` must be regenerated too: how, under "Speed suite" in the README. See [`.claude/specs/simulator/spec.md`](.claude/specs/simulator/spec.md) for the specification and [`simulator/README.md`](simulator/README.md) for how to run it.

## Conventions

- Inter ships as `src/ui/fonts/Inter.woff2`, a 15KB cut of Inter 4.1: ASCII plus `· × − – — …`, weights 400 to 800. A UI string with any other character renders that character in the system font, so cut the file again when adding one: `fonttools varLib.instancer InterVariable.ttf opsz=14 wght=400:800`, then `pyftsubset --unicodes=... --layout-features=kern,tnum --name-IDs=0,1,2,3,4,5,6,13,14 --flavor=woff2`.
- CI runs the app gates and Rust debug and release tests before dispatching a site rebuild.
- Full-page Chromium screenshots briefly resize to 1x1 and can mount the other responsive tree. Use viewport screenshots when asserting local selection or open-menu state afterward.
- Simulator changes run `cargo test` in BOTH profiles from `simulator/`. Never let `HashMap` iteration or float accumulation order reach an output. Why, in [`contracts.md`](.claude/specs/simulator/contracts.md).
- Simulator seed domains are spend-once, and the first nine are spent: `tuning`, `eval`, `gate`, `eval2` and `gate2` are used up, `tuning2` was SP6's screening domain, and the seat-count programme screened on `tuning3` and spent `eval3` and `gate3` once at every seat count from two to six. Never run a command carrying any of them. In those three generations seat count does not change the generated boards, so a domain is held out per layout, never per seat count. The fourth generation (`tuning4`, `eval4`, `gate4`) folds the seat count into its seed, so its ledger is per seat count: `gate4` is spent at two to six seats, and `tuning4` and `eval4` are unspent. Mint a new generation whenever a phase needs one, without asking. Why, the spend ledger, and the phase order, in [`programme.md`](.claude/specs/simulator/programme.md).
- A draft-aware placement arm is spelled `app_formula_draft:<hero weights>@<opponent weights>`, and its opponent path is pinned to the field's weights so an A/B moves the hero's formula alone. Why, in [`contracts.md`](.claude/specs/simulator/contracts.md).
- Every `sp2` through `sp6` weights arm is a perturbation of `simulator/placement/sp6-pre-adoption-weights.json`, not of the live defaults, because the SP6 adoption moved `expansionWeight` after they were measured. Anchor a new arm to whichever vector its own run is against, and say which in its pin test.
- Placement weights are chosen by roster size alone, and the JSON files under `simulator/placement/` are their source of truth: `weights_for_seats` (`placement/analysis.rs`) reads `seat-weights/seats-<n>.json` for two to six players and `default-weights.json` otherwise, embedded in the engine with `include_str!`. The simulator reads the same files through the `{seats}` placeholder. Move a seat count's vector only with its `SEAT_ADOPTIONS` row in `params_file.rs`, whose test holds each file to the defaults plus exactly those leaves. Every `sc_*` arm is a perturbation of the live `default-weights.json`, which no seat-count adoption moved. What each seat count ships and why, in [`seat-count-programme.md`](.claude/specs/simulator/seat-count-programme.md).
- Parser correctness is guarded by the three `fixtures/settled-*.png` snapshots in `src/parser/__tests__/expected/`. Regenerating expected output means re-verifying it by hand. The retained endgame PNG, sRGB twin and expected JSON cover cities and roads by player colour; their old header is not parsed. `expected/board-draft-empty.json` has no screenshot any more: it stays as the board the engine tests and the simulator load.
- Cross-window sync (`ui/workspaceSync.ts`) is timing-sensitive, so a test for it is worthless until it has been shown to fail against the code it was written for. Two paces matter: a close pace under the 500ms autosave debounce coalesces into one write and races nothing, and a second window that is merely open (rather than also being written in) never answers mid-sequence. Both make a green run meaningless.
- `.claude/worktrees` holds full repo copies; `vite.config.ts` excludes it from vitest so tests don't double-run.
- Change anything under `simulator/crates/engine/src`, `simulator/crates/wasm`, `simulator/topology` or the workspace manifests and you must run `simulator/tools/build-wasm.sh` and commit the new `engine.wasm` and hash, or CI fails. If advice output changed, also regenerate `simulator/fixtures/advice-parity.json` (`cargo test -p unsettled-engine --test advice_parity -- --ignored regenerate`) and re-verify it: `advice_parity.rs` checks it natively and `wasmParity.test.ts` checks the committed wasm returns the same JSON, which is the bit-identity gate for scores. Then regenerate `simulator/fixtures/bench-hashes.json`, whose `advise` rows hash that fixture's requests and responses.
- The adviser never recommends building a super city, treats a rival's dev cards as unplayed knights, and ignores the observer's cards of unknown type; the panel's notes say so whenever one applies. The engine refuses boards the app only warns about (a blank tile, a resource hex with no number, one player, no robber and no desert, adjacent buildings): `adviceBlockers` in `ui/bestMoves.ts` lists what to finish and the panel asks for no advice until it is empty. No boons or curses hook.
