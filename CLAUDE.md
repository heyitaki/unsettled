# CLAUDE.md

Guidance for Claude Code in this repository.

## What this is

Unsettled: an offline, browser-only Catan starting-position analyzer (React 19 + TS + Vite). No backend: all state lives in `localStorage`. Phase 1 (board editor + screenshot import) and Phase 2 (rank the best placements for your picks in a snake draft, accounting for intermediate picks) are done. Phase 3 (boons/curses expansion scoring) is paused: do not start it before the user supplies the full boon/curse list. See the `catan-companion-roadmap` project memory note, which lives outside the repo.

## Commands

- `npm run dev`: Vite dev server
- `npm test`: unit tests, then `src/engine/__tests__/perf.test.ts` on its own so the performance guard never measures test-runner contention. Watch: `npx vitest`. One file: `npx vitest run src/model/__tests__/board.test.ts`. By name: `npx vitest run -t "substring"`
- `npm run test:e2e`: Playwright specs in `e2e/`, on their own dev server at port 5199. Specs import app modules (`tsconfig.e2e.json` resolves like the app), so pin an assertion to the constant it checks. `e2e/seed.ts` seeds an unclaimed roster: a fresh board boots with one player already claimed, so any test of the claim row seeds the stored workspace and reloads. Phone tests use the `test.use` block at the top of `phoneShell.spec.ts`; never spread a `devices[...]` preset, which selects WebKit (not installed). Screenshots land in `test-results/phone/`. To check a regression test really bites, point it at a worktree of an older commit: `UNSETTLED_E2E_PORT=5201 UNSETTLED_E2E_ROOT=<worktree> npm run test:e2e`
- `npm run test:pwa`: production-build Playwright checks in `e2e/production/` on port 5200 (`npm run build` first). Artifacts go under `test-results/production/`.
- `npm run typecheck`: `tsc -b` (strict; no `any`)
- `npm run lint`: `oxlint`
- `npm run build`: typecheck + Vite build

## Architecture

Data flows from `parser/` to `model/Board`, then to `engine/` and `ui/store`, then to `persistence/`. The `Board` interface (`model/types.ts`) is the single source of truth passed between all layers. A `Game` (`model/game.ts`) wraps a `Board` with the per-player state that cannot be derived from the pieces (hands, dev cards, knights, VP cards, award holders); tabs, the library, and import/export all persist whole games; storage shapes older than the `Game` envelope are no longer read.

- **`model/`**: pure geometry + board logic, no React. `coords.ts` is the foundation: axial `{q,r}` hex coords; `VertexId`/`EdgeId` are deterministic strings built from **sorted** member coords (`v:q,r;q,r;q,r`), so any corner/edge has one canonical id regardless of which hex references it. `layouts.ts` defines the `standard4`/`extension6` grids and default port edges. `serialization.ts` validates untrusted board JSON with exact-key structural checks; `board.ts` builds/validates boards. `Game.awards` records the Longest Road and Largest Army holders: a qualifying incumbent keeps a tie, an imported tie stays unknown until corrected through `AwardControls`, and games saved before the field still load.
- **`engine/`**: pure placement analysis, no React: draft-state inference from building counts, legality, weighted valuation with per-factor breakdowns, seeded opponent rollouts (`analyzeBoard`), whose modal pre-window (the `Likely gone` line) takes each rival's top recommendation from a nested analysis, so it matches the list that rival is shown and costs one extra full ranking per rival pick ahead of the claimed seat. Sampled pre-windows draw from that rival's same ranked list while they follow the modal line; once they leave it, and in all mid-windows, picks come from `opponentPick`, which prices a rival's first settlement as a pair from a per-analysis partner table and takes the half worth more alone first. Scoring also takes the board's occupancy (blocked vertices plus road owners, for `expansion.ts`'s walk) and the picking seat's draft slot. Phase 3 boons/curses have no hook yet; add one when the list arrives rather than carrying an empty plumbing layer. The UI runs `analyzeBoard` only in `analysis.worker.ts`, never during render: `AnalysisProvider` shares one worker result across the active board's panels and marks, and `analysisClient` cancels obsolete jobs and caches results by board identity. `DraftGrid`, `DraftRibbon` and roster labels use cheap draft inference without rollouts. Four- and six-seat analysis are both expensive, so do not add work per rollout scan casually.
- **`parser/`**: offline screenshot to `Game`. `parseScreenshot` (`index.ts`) calls the Settled steps directly: `registration` fits the hex grid and bounds the board, then `tiles`/`tokens`/`ports`/`pieces` read its content over one `components.ts` labeler. `sources/settled/` supplies the palette and player-pill reader. Pills give turn order, colour names, hand counts and the highlighted player to claim; VP is cross-checked against parsed buildings and possible public awards. Settlement badges order each player's picks before buildings are emitted in snake order. Synchronous parsing is pure pixel analysis and emits `ParseIssue[]` rather than throwing. Screenshots with no pills synthesize players from piece colours.
- **`ui/`**: `store.ts` is a `useReducer` context holding multiple `TabState`s (each an independent game with its own `past`/`future` undo stacks over whole `Game`s) plus the active `Tool`. Board edits dispatch `commit` with the next `Board` and the reducer wraps it via `withBoard`; stat edits dispatch `commit-game`. Wider than 760px `App` mounts the desktop `Workspace`; at phone widths (`max-width: 760px`, any orientation) it mounts `phone/PhoneShell` instead, gated by `usePhone`. The two trees share `AnalysisPanel` and `DraftRibbon` outright, and the Library and roster logic through hooks (`useLibrary`, `useRenameTab`, `useJsonFiles`, `useRowReorder`). The Best picks step buttons (`useDraftSteps`) commit each step as an ordinary edit and keep their forward list in the hook, outside the store's undo stacks. `glyphs.tsx` is the one home for inline SVG icons (one flat family on a 20-unit grid; the board draws its own piece shapes). Boards are switched from the Library; neither tree has tabs, an import panel or a footer. The workspace tree is built to [`.claude/specs/desktop/spec.md`](.claude/specs/desktop/spec.md) and the phone shell to [`.claude/specs/mobile/spec.md`](.claude/specs/mobile/spec.md), so read both before touching `src/ui/phone/`, a promoted base rule or the `max-width: 760px` arm of `editor.css`. Modals mount through `ModalDialog`, a native `<dialog>` that makes the rest of the page inert, closes on Escape and hands focus back to its opener, so never hand-roll a focus trap. `ContextMenu` is a native popover anchored in CSS rather than positioned from JS.
- **`persistence/`**: `localStorage.ts` saves the whole workspace (`WORKSPACE_KEY`) and named maps (`MAPS_KEY`), and corrupt blobs are preserved under `*.corrupt` keys instead of being discarded. Boards autosave into the library (`ui/libraryAutosave.ts`, 500ms debounce, and an unlinked tab links to a new map on its first non-blank edit), so there is no save button, dirty marker or close prompt anywhere. `isFreshGame` (`model/serialization.ts`) is the one rule for "nothing beyond a fresh board of its layout", shared by the autosave and the backup. The library keeps `MAX_MAPS` (50) entries: a new map beyond that evicts the least recently touched ones, and the autosave closes any tab linked to an evicted map so it cannot re-save itself past the cap. `backup.ts` exports the library plus open games and preserved corrupt blobs. Restore validates every entry before one write, merges without overwriting, and tests the cap after the merge rather than against the file's own length.
- **`simulator/`**: separate Rust workspace (outside the Vite build and `npm test`) that self-plays games to measure which starting placements win. Never hand-edit `simulator/topology/*.json`. Change either placement scorer and you must regenerate and re-verify `simulator/fixtures/placement-parity.json`; `placementParity.test.ts` checks the committed fixture and default weights against the TypeScript scorer without rewriting them. See [`.claude/specs/simulator/spec.md`](.claude/specs/simulator/spec.md) for the specification and [`simulator/README.md`](simulator/README.md) for how to run it.

## Conventions

- CI runs the app gates and Rust debug and release tests before dispatching a site rebuild.
- Full-page Chromium screenshots briefly resize to 1x1 and can mount the other responsive tree. Use viewport screenshots when asserting local selection or open-menu state afterward.
- Simulator changes run `cargo test` in BOTH profiles from `simulator/`. Never let `HashMap` iteration or float accumulation order reach an output. Why, in [`contracts.md`](.claude/specs/simulator/contracts.md).
- Simulator seed domains are spend-once, and all six are now spent: `tuning`, `eval`, `gate`, `eval2` and `gate2` are used up, and `tuning2` was SP6's screening domain. Never run a command carrying any of them; a future placement phase must mint a third generation first. Why, the spend ledger, and the phase order, in [`programme.md`](.claude/specs/simulator/programme.md).
- A draft-aware placement arm is spelled `app_formula_draft:<hero weights>@<opponent weights>`, and its opponent path is pinned to the field's weights so an A/B moves the hero's formula alone. Why, in [`contracts.md`](.claude/specs/simulator/contracts.md).
- Every `sp2` through `sp6` weights arm is a perturbation of `simulator/placement/sp6-pre-adoption-weights.json`, not of the live defaults, because the SP6 adoption moved `expansionWeight` after they were measured. Anchor a new arm to whichever vector its own run is against, and say which in its pin test.
- Parser correctness is guarded by the three `fixtures/settled-*.png` snapshots in `src/parser/__tests__/expected/`. Regenerating expected output means re-verifying it by hand. The retained endgame PNG, sRGB twin and expected JSON cover cities and roads by player colour; their old header is not parsed. `expected/board-draft-empty.json` has no screenshot any more: it stays as the board the engine tests and the simulator load.
- Cross-window sync (`ui/workspaceSync.ts`) is timing-sensitive, so a test for it is worthless until it has been shown to fail against the code it was written for. Two paces matter: a close pace under the 500ms autosave debounce coalesces into one write and races nothing, and a second window that is merely open (rather than also being written in) never answers mid-sequence. Both make a green run meaningless.
- `.claude/worktrees` holds full repo copies; `vite.config.ts` excludes it from vitest so tests don't double-run.
