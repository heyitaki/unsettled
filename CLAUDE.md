# CLAUDE.md

Guidance for Claude Code in this repository.

## What this is

Unsettled: an offline, browser-only Catan starting-position analyzer (React 19 + TS + Vite). No backend: all state lives in `localStorage`. Once a draft is finished the same panel shows a draft recap (each player's hand and their win chance from self-play in the same engine) and, from `Start game` on, becomes the move adviser (Best moves), which tracks turns and ranks every in-game decision with the Rust turn policy. Both rankings are computed by the Rust engine under `simulator/`, compiled to one committed WebAssembly file and run in workers; the TypeScript under `src/engine/` handles rendering helpers and the wasm clients. Phase 3 (boons/curses expansion scoring) is paused: do not start it before the user supplies the full boon/curse list. See the `catan-companion-roadmap` project memory note, which lives outside the repo.

## Commands

- `npm run dev`: Vite dev server
- `npm test`: unit tests, then `src/engine/__tests__/perf.test.ts`, `src/engine/advice/__tests__/advicePerf.test.ts` and `src/engine/__tests__/analysisPerf.test.ts`, each in its own run so a performance guard never measures test-runner contention. A new perf file joins both the exclude list and the tail of that script. Watch: `npx vitest`. One file: `npx vitest run src/model/__tests__/board.test.ts`. By name: `npx vitest run -t "substring"`
- `npm run test:e2e`: Playwright specs in `e2e/`, on their own dev server at port 5199. Specs import app modules (`tsconfig.e2e.json` resolves like the app), so pin an assertion to the constant it checks. `e2e/seed.ts` seeds an unclaimed roster: a fresh board boots with one player already claimed, so any test of the claim row seeds the stored workspace and reloads. A finished draft seeded with no turn opens on the draft recap, so a Best moves test passes `seedBoard` a `turn`. Phone tests use the `test.use` block at the top of `phoneShell.spec.ts`; never spread a `devices[...]` preset, which selects WebKit (not installed). The board's placement dots take no pointer events, so click one by coordinates or with `{ force: true }`. To check a regression test really bites, point it at a worktree of an older commit: `UNSETTLED_E2E_PORT=5201 UNSETTLED_E2E_ROOT=<worktree> npm run test:e2e`
- `npm run test:pwa`: production-build Playwright checks in `e2e/production/` on port 5200 (`npm run build` first). Artifacts go under `test-results/production/`.
- `npm run typecheck`: `tsc -b` (strict; no `any`)
- `npm run lint`: `oxlint`
- `npm run build`: typecheck + Vite build. Needs no Rust toolchain: the engine behind Best picks and Best moves is the committed `src/engine/advice/engine.wasm`.
- `npm run ios:build`: typecheck, the iOS bundle (`vite build --mode native` into `dist-native/`, base `/`, no service worker) and `cap sync ios`. Then build and run `ios/App/App.xcodeproj` (scheme `App`) from Xcode or `xcodebuild`. Needs `ota/keys/bundle.pub` (or `UNSETTLED_OTA_BUNDLE_PUBLIC_KEY_FILE`) and fails without it, and full git history, since the built-in OTA label is `1.0.<commit count>`.
- `npm run ios:archive`: runs `ios/archive.sh`, which builds only from `origin/main`: it refuses a shallow clone, fetches, runs `npm ci` and `ios:build` in a temporary clean worktree with every `UNSETTLED_OTA_*` and `VITE_OTA_*` variable unset, refuses if `cap sync` rewrote a tracked file, then writes a Release archive to `ios/App/build/Unsettled.xcarchive` in this checkout, numbered by the current UTC time and signed ad hoc with each target's entitlements (the script says why). It tags that commit `store/ios/<build>` locally and prints the push command; push the tag only after `npm run ios:upload` succeeds, since the OTA publish reads those tags. `npm run ios:upload` sends the archive to App Store Connect (TestFlight) with `ios/ExportOptions.plist`, authenticated by the Apple account signed into Xcode; if that fails, Distribute App from the Xcode Organizer.
- `npm run ota:harness`: the OTA end-to-end proof on the booted iPhone simulator (`tools/ota/harness/`, 30 to 50 minutes, wipes the simulator's Unsettled data). Not part of `npm test`; rerun it after changing `src/native/`, `src/main.tsx`, `capacitor.config.ts` or `tools/ota/`. Run it in the foreground and never alongside a test suite. `-- --only 1,2` runs chosen scenarios. It leaves `dist-native/` and the synced iOS project as a harness build, so run `ios:build` before building from Xcode again.
- `simulator/tools/build-wasm.sh`: rebuilds that file and `engine.wasm.src-hash` (needs the `wasm32-unknown-unknown` target). `--check` verifies the source hash and the binary's checksum without Rust, and is what CI runs.

## Architecture

Data flows from `parser/` to `model/Board`, then to `engine/` and `ui/store`, then to `persistence/`. The `Board` interface (`model/types.ts`) is the single source of truth passed between all layers. A `Game` (`model/game.ts`) wraps a `Board` with the per-player state that cannot be derived from the pieces (hands, dev cards, knights, VP cards, award holders, and after the draft `turn` and the claimed player's `devHand` by type); tabs, the library, and import/export all persist whole games; storage shapes older than the `Game` envelope are no longer read.

- **`model/`**: pure geometry + board logic, no React. `coords.ts` is the foundation: axial `{q,r}` hex coords; `VertexId`/`EdgeId` are deterministic strings built from **sorted** member coords (`v:q,r;q,r;q,r`), so any corner/edge has one canonical id regardless of which hex references it. `serialization.ts` validates untrusted board JSON with exact-key structural checks. Before the first recorded turn, `withBoard` deals starting resources when the draft completes and updates or takes them back on later board edits only for hands matching the old setup grant with no unknown cards. In `Game.awards` a qualifying incumbent keeps a tie. `turn.ts` holds one pure function per recorded in-game action, each returning the next `Game`. `Game.history` stores the starting position and finished turns as changes (pieces, and the stats of players whose stats changed), while `turn.log` persists the current turn's action lines; `historyGame` folds a read-only past view over live terrain and ports. `Game.turn.playerId` is whose turn it is and who recorded actions are for; Best moves follows the temporary store `viewedPlayer` (null means the turn player), which resets on tab switches and turn-player changes; `board.mePlayerId` means only "the player whose cards are known exactly". A rival's hand is a known lower bound per resource plus `handUnknown` cards nobody saw. The typed `devHand` is dropped whenever it would exceed the player's public dev card count.
- **`engine/`**: the app's side of the two rankings, no React. Best picks itself is Rust, `simulator/crates/engine/src/placement/analysis.rs`, compiled into the committed `advice/engine.wasm`; no TypeScript analysis or placement formula exists any more. `setupRoad.ts` is the one engine call the UI makes outside a worker. The analysis accepts every board `validateBoard` accepts, including the ones the adviser refuses. `analysisProtocol.ts` mirrors the JSON the Rust writes. The analysis runs only in `analysis.worker.ts`, never during render. `analysisClient` cancels obsolete jobs by terminating the worker, which drops the nested-ranking cache with it. Draft inference is the one piece of logic in both languages: `infer_draft_state` in `analysis.rs` fills the `draft` field of every ranking, so change it and `draft.ts` together; `draftParity.test.ts` holds `draft.ts` to the fixture's responses. `analysisPerf.test.ts` bounds the two worst six-seat rankings, so do not add work per rollout scan casually; a fast path in a scan must return the reference path's bits, which debug and test builds assert on every call. `engine/advice/wasm.ts` is the one loader for the committed `engine.wasm` (no `wasm-bindgen`), and each worker runs its own instance. The `recap` decision on the `advise` export plays whole games from a finished draft (`recap.rs`, `GameArena::play_from_draft`) and returns win counts; native and wasm are each repeatable but may differ from each other, so it has no parity fixture row. A test that needs a real ranking calls `src/engine/__tests__/analyzeWasm.ts`, which loads the committed wasm.
- **`parser/`**: offline screenshot to `Game`, from two sources. `parseScreenshot` (`index.ts`) tries the Colonist.io game screen (`sources/colonist/`) first, which turns down any image without Colonist's sea blue, and otherwise runs the Settled steps: `registration` fits the hex grid and bounds the board, then `tiles`/`tokens`/`ports`/`pieces` read its content over one `components.ts` labeler. A failed Colonist parse falls through to Settled, whose error stands if both fail; Settled's palette check cannot be the switch because it accepts some Colonist screens. Colonist's panel is rotated to put the viewer last and shows no pick order, so the first player is known only mid-draft and a player's two settlements carry a warning that their order is unknown. Synchronous parsing is pure pixel analysis and emits `ParseIssue[]` rather than throwing. What is and is not covered, in [`.claude/specs/colonist/plan.md`](.claude/specs/colonist/plan.md).
- **`ui/`**: `store.ts` is a `useReducer` context holding multiple `TabState`s (each an independent game with its own `past`/`future` undo stacks over whole `Game`s) plus the active `Tool`. Board edits dispatch `commit` with the next `Board` and the reducer wraps it via `withBoard`; stat edits dispatch `commit-game`. Wider than 760px `App` mounts the desktop `Workspace`; at phone widths (`max-width: 760px`, any orientation) it mounts `phone/PhoneShell` instead, gated by `usePhone`. The workspace tree is built to [`.claude/specs/desktop/spec.md`](.claude/specs/desktop/spec.md) and the phone shell to [`.claude/specs/mobile/spec.md`](.claude/specs/mobile/spec.md), which hold every click, tap, draft-step and panel rule, so read both before touching `src/ui/phone/`, a promoted base rule or the `max-width: 760px` arm of `editor.css`. The two trees share components and hooks rather than forking them. Best picks views a pick independently of the claim: the store's `viewedPick` is a draft slot of any player (null means the claimed player's next pick), and `AnalysisProvider` analyses the board as the viewed player (`viewedPlayerId` in `draftSlots.ts`), so the cards, marks and `Place settlement` follow that player. The Best picks step buttons (`useDraftSteps`) commit each step as an ordinary edit and keep their forward list in the hook, outside the store's undo stacks. A tray that needs a spot on the board sets the store's `pick`, and while it is set `BoardCanvas` routes clicks to it instead of the active tool. `useBoardActions` is the one home for randomize, clear and the layout switch, `UndoRedoButtons` the one undo and redo pair, and `glyphs.tsx` the one home for icons (one flat family on a 20-unit grid, except the board, the brand mark and the dice pips, which draw their own). The import dialog is the panel's sibling so it survives the swap. A screenshot of a saved board's terrain updates it through `mergeScreenshot`, which never lets a value the screenshot did not read overwrite a saved one. Modals mount through `ModalDialog`, a native `<dialog>` that makes the rest of the page inert, closes on Escape and hands focus back to its opener, so never hand-roll a focus trap. `ContextMenu` is a native popover anchored in CSS rather than positioned from JS.
- **`persistence/`**: `localStorage.ts` saves the whole workspace (`WORKSPACE_KEY`) and named maps (`MAPS_KEY`), and corrupt blobs are preserved under `*.corrupt` keys instead of being discarded; quota failures clear the analysis cache and retry once before a shared confirmation offers to clean up old closed games, with the same action in a Maps warning while the prompt is closed. Boards autosave into the library (`ui/libraryAutosave.ts`, 500ms debounce, and an unlinked tab links to a new map on its first non-blank edit), so there is no save button, dirty marker or close prompt anywhere. `isFreshGame` (`model/serialization.ts`) is the one rule for "nothing beyond a fresh board of its layout", shared by the autosave and the backup. The library keeps `MAX_MAPS` (50) entries: a new map beyond that evicts the least recently touched ones, and the autosave closes any tab linked to an evicted map so it cannot re-save itself past the cap. Restore validates every entry before one write, merges without overwriting, and tests the cap after the merge rather than against the file's own length.
- **OTA (iOS only)**: the native app takes web bundle updates through `@capgo/capacitor-updater` in manual mode with every Capgo URL blank (`capacitor.config.ts`). `src/native/otaDecisions.ts` holds the pure decisions, `ota.ts` the plugin adapter and `otaStatus.ts` the in-memory version line and update link state; `src/main.tsx` reaches them only through the native-mode dynamic import, so the website build carries none of it. A downloaded bundle applies only at cold start, before React mounts; `StoreProvider`'s first mount effect calls `notifyAppReady()` and then checks the manifest. A bundle that never calls it within 10 s is rolled back by the plugin and never downloaded again on that store build. The site deploy runs `tools/ota/publish.mjs --out <dir> --base-url <url>` with `OTA_BUNDLE_PRIVATE_KEY` set (it refuses a shallow clone, no `store/ios/*` tag or no key, and writes the bundle before `ios.json`), which sets the manifest's `minNativeBuild` from the latest uninterrupted run of `store/ios/*` tags whose native fingerprint (a hash of `ios/App/`, `capacitor.config.ts`, `ota/keys/bundle.pub`, `ota/native-epoch` and the lockfile versions of the plugins `Package.swift` references) equals HEAD's; with no match no phone downloads it and every phone shows the update link until a matching store build is tagged. Bump the integer in `ota/native-epoch` when a change would break older bundles on the same native build after a rollback (for example a stored-data format they cannot read): that forces a store build.
- **`simulator/`**: separate Rust workspace (outside the Vite build; `npm test` reaches it only through the committed wasm and the fixtures under `simulator/fixtures/`) that self-plays games to measure which starting placements win, and whose engine crate is also what the app runs for Best picks and Best moves. Never hand-edit `simulator/topology/*.json`. Best picks runs over the one placement scorer, `placement/app_formula.rs`, which the simulator runs natively. Change the placement scorer, the analysis or a shipped weight value and you must regenerate `simulator/fixtures/analysis-parity.json` (`cargo test --release -p unsettled-engine --test analysis_parity regenerate -- --ignored`) and re-verify its diff by hand. `analysis_parity.rs` checks it natively by exact JSON equality and `wasmAnalysisParity.test.ts` checks the committed wasm against it, exactly for every case outside its `LAST_BIT_CASES` list. Why that list exists, in [`contracts.md`](.claude/specs/simulator/contracts.md). `crates/engine/src/advice.rs` is the adviser's bridge: it builds a policy view from the app's game JSON and returns advice with a one-line reason from the scorer's own terms, never changing a score; `crates/wasm` exports it. Change a scorer, a policy or the rules and `simulator/fixtures/bench-hashes.json` must be regenerated too: how, under "Speed suite" in the README. See [`.claude/specs/simulator/spec.md`](.claude/specs/simulator/spec.md) for the specification and [`simulator/README.md`](simulator/README.md) for how to run it.

## Conventions

- Inter ships as `src/ui/fonts/Inter.woff2`, a 15KB cut of Inter 4.1: ASCII plus `· × − – — …`, weights 400 to 800. A UI string with any other character renders that character in the system font, so cut the file again when adding one: `fonttools varLib.instancer InterVariable.ttf opsz=14 wght=400:800`, then `pyftsubset --unicodes=... --layout-features=kern,tnum --name-IDs=0,1,2,3,4,5,6,13,14 --flavor=woff2`.
- UI copy capitalizes the first letter after a ` · ` separator (`Red · Not rolled yet`, `Robber to Wheat 8 · Stole from Blue`); a comma continues a sentence in lowercase.
- CI (`notify-site.yml`, workflow "Check and deploy") runs the app gates, e2e and Rust debug and release tests. The Rust jobs run only when a path in its `changes` filter moved, so a file outside `simulator/` that a Rust test starts reading joins that filter. `dispatch-site.yml` pings the site only after a green push run on main, and the site publishes the newest commit with a green run. Never rename that file or that workflow: the site's `jekyll.yml` and the dispatch find it by both.
- Full-page Chromium screenshots briefly resize to 1x1 and can mount the other responsive tree. Use viewport screenshots when asserting local selection or open-menu state afterward.
- Simulator changes run `cargo test` in BOTH profiles from `simulator/`. Never let `HashMap` iteration or float accumulation order reach an output. Why, in [`contracts.md`](.claude/specs/simulator/contracts.md).
- Simulator seed domains are spend-once, and the first nine are spent: `tuning`, `eval`, `gate`, `eval2` and `gate2` are used up, `tuning2` was SP6's screening domain, and the seat-count programme screened on `tuning3` and spent `eval3` and `gate3` once at every seat count from two to six. Never run a command carrying any of them. In those three generations seat count does not change the generated boards, so a domain is held out per layout, never per seat count. The fourth generation (`tuning4`, `eval4`, `gate4`) folds the seat count into its seed, so its ledger is per seat count: `gate4` and `tuning4` are spent at two to six seats, and `eval4` is spent at six seats and unspent at two to five. The cut-off gate `gate5` (`0x6a75_5eed_2026_1012`) uses the same per-seat recipe; it is spent at four and six seats (M-117, M-118) and unspent at two, three and five. The board-strategy domains `tuning5`, `tuning6`, `eval5` and `gate6` use the same per-seat recipe: `tuning5` and `tuning6` are spent at three to six seats (M-120 to M-127) and unspent at two, `eval5` and `gate6` are spent at five seats (M-128, M-129) and unspent elsewhere. Mint a new generation whenever a phase needs one, without asking. Why, the spend ledger, and the phase order, in [`programme.md`](.claude/specs/simulator/programme.md). `perf` is a repeatable domain derived from `PERF_SEED` and the seat count, for timing and memory readings only, never evidence, never spent.
- A draft-aware placement arm is spelled `app_formula_draft:<hero weights>@<opponent weights>`, and its opponent path is pinned to the field's weights so an A/B moves the hero's formula alone. Why, in [`contracts.md`](.claude/specs/simulator/contracts.md).
- Every `sp2` through `sp6` weights arm is a perturbation of `simulator/placement/sp6-pre-adoption-weights.json`, not of the live defaults, because the SP6 adoption moved `expansionWeight` after they were measured. Anchor a new arm to whichever vector its own run is against, and say which in its pin test.
- Placement weights are chosen by roster size, and at five seats also by the player's draft slot and the board's terrain through `seat-strategies/seats-5.json`. Its `slot>=1&topCrowding>=10` rule applies `contestWeight` 0.5 and `repriceFirstExpansion` 1 over `seats-5.json`; explicit `options.weights` bypasses selection. The JSON files under `simulator/placement/` are their source of truth: `weights_for_seats` (`placement/analysis.rs`) reads `seat-weights/seats-<n>.json` for two to six players and `default-weights.json` otherwise, embedded in the engine with `include_str!`. The simulator's `app_formula_shipped` uses the same selection; explicit arms read seat vectors through the `{seats}` placeholder. No generator writes them any more, so a weight is edited in the JSON by hand. Move a seat count's vector only with its `SEAT_ADOPTIONS` row in `params_file.rs`, whose test holds each file to the defaults plus exactly those leaves; `default-weights.json` itself is pinned only by the analysis fixture's responses. Every `sc_*` arm is a perturbation of the live `default-weights.json`, which no seat-count adoption moved. What each seat count ships and why, in [`seat-count-programme.md`](.claude/specs/simulator/seat-count-programme.md).
- Parser correctness is guarded by the four `fixtures/settled-*.png` snapshots and their expected JSON in `src/parser/__tests__/expected/`. Regenerating expected output means re-verifying it by hand. Colonist screenshots are not in the repo (its terms require credit on published screenshots): they live in the ignored `fixtures/colonist.local/`, `colonist.test.ts` and `colonistDamage.test.ts` skip without that folder, so CI never runs them and a parser change is checked on a machine that has them. The expected boards were read by eye and are written in `colonist.test.ts` itself; a new worktree needs the folder copied in (`cp -c -R`). `expected/board-draft-empty.json` has no screenshot any more: it stays as the board the simulator's tests, the e2e specs and `finishedDraft.ts` load.
- Cross-window sync (`ui/workspaceSync.ts`) is timing-sensitive, so a test for it is worthless until it has been shown to fail against the code it was written for. Two paces matter: a close pace under the 500ms autosave debounce coalesces into one write and races nothing, and a second window that is merely open (rather than also being written in) never answers mid-sequence. Both make a green run meaningless.
- `.claude/worktrees` holds full repo copies; `vite.config.ts` excludes it from vitest so tests don't double-run.
- Change anything under `simulator/crates/engine/src`, `simulator/crates/engine/Cargo.toml`, `simulator/crates/wasm`, `simulator/topology`, `simulator/placement/default-weights.json`, `simulator/placement/seat-weights`, or `simulator/Cargo.toml` and `Cargo.lock`, and you must run `simulator/tools/build-wasm.sh` and commit the new `engine.wasm` and hash, or CI fails. A comment-only edit still moves the hash, and can move the binary through its panic line numbers. If Best picks output changed, regenerate `simulator/fixtures/analysis-parity.json` as the `simulator/` paragraph above says. If advice output changed, also regenerate `simulator/fixtures/advice-parity.json` (`cargo test -p unsettled-engine --test advice_parity -- --ignored regenerate`) and re-verify it: `advice_parity.rs` checks it natively and `wasmParity.test.ts` checks the committed wasm returns the same JSON, which is the bit-identity gate for scores. Then regenerate `simulator/fixtures/bench-hashes.json`, whose `advise` rows hash that fixture's requests and responses and whose `analyze` rows hash three rankings of two boards from the analysis fixture.
- The adviser never recommends building a super city, treats a rival's dev cards as unplayed knights, and ignores the observer's cards of unknown type; the panel's notes say so for the last two whenever one applies. The engine refuses boards the app only warns about (a blank tile, a resource hex with no number, one player, no robber and no desert, adjacent buildings): `adviceBlockers` in `ui/bestMoves.ts` lists what to finish and the panel asks for no advice until it is empty. No boons or curses hook.
