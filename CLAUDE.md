# CLAUDE.md

Guidance for Claude Code in this repository.

## What this is

Unsettled: an offline, browser-only Catan starting-position analyzer (React 19 + TS + Vite), with all state in `localStorage`. Best picks ranks draft placements, a finished draft shows a recap with self-play win chances, and from `Start game` on Best moves ranks every in-game decision. All of it runs the Rust engine under `simulator/`, compiled to one committed WebAssembly file run in workers. Phase 3 (boons/curses scoring) is paused until the user supplies the full boon/curse list (see the `catan-companion-roadmap` project memory note).

## Commands

- `npm run dev`: Vite dev server
- `npm test`: unit tests, then each perf file in its own run so a perf guard never measures runner contention. A new perf file joins both the exclude list and the tail of that script. One file: `npx vitest run <path>`. By name: `npx vitest run -t "substring"`
- `npm run test:e2e`: Playwright specs in `e2e/` on their own dev server at port 5199. Specs import app modules, so pin an assertion to the constant it checks. A fresh board boots with one player claimed, so a claim-row test seeds the workspace (`e2e/seed.ts`) and reloads. A seeded finished draft with no turn opens on the recap, so a Best moves test passes `seedBoard` a `turn`. Phone tests use the `test.use` block atop `phoneShell.spec.ts`. Never spread a `devices[...]` preset (it selects WebKit, not installed). Placement dots take no pointer events: click by coordinates or `{ force: true }`. To prove a regression test bites, run it against an older worktree: `UNSETTLED_E2E_PORT=5201 UNSETTLED_E2E_ROOT=<worktree> npm run test:e2e`
- `npm run test:pwa`: production-build checks in `e2e/production/` on port 5200 (`npm run build` first).
- `npm run typecheck`: `tsc -b` (strict, no `any`). `npm run lint`: `oxlint`
- `npm run build`: typecheck + Vite build. Needs no Rust toolchain.
- `npm run ios:build`: typecheck, the native bundle into `dist-native/` and `cap sync ios`, then build `ios/App/App.xcodeproj` (scheme `App`). Fails without `ota/keys/bundle.pub` (or `UNSETTLED_OTA_BUNDLE_PUBLIC_KEY_FILE`) or without full git history (the OTA label is `1.0.<commit count>`).
- `npm run ios:archive`: `ios/archive.sh` builds a Release archive from a clean `origin/main` worktree into `ios/App/build/Unsettled.xcarchive` and tags the commit `store/ios/<build>` locally. Push the tag only after `npm run ios:upload` (TestFlight, via the Apple account in Xcode) succeeds, since the OTA publish reads those tags. If the upload fails, use Distribute App in the Xcode Organizer.
- `npm run ota:harness`: OTA end-to-end proof on the booted iPhone simulator (30 to 50 minutes, wipes the simulator's app data). Rerun it after changing `src/native/`, `src/main.tsx`, `capacitor.config.ts` or `tools/ota/`. Run it in the foreground, never alongside a test suite. `-- --only 1,2` picks scenarios. Run `ios:build` before building from Xcode again.
- `simulator/tools/build-wasm.sh`: rebuilds `engine.wasm` and `engine.wasm.src-hash` (needs the `wasm32-unknown-unknown` target). `--check` verifies both without Rust and is what CI runs.

## Architecture

The `Board` interface (`model/types.ts`) is the single source of truth between `parser/`, `model/`, `engine/`, `ui/` and `persistence/`. A `Game` (`model/game.ts`) wraps it with the state pieces cannot show, and tabs, the library and import/export all persist whole games. Storage shapes older than `Game` are not read.

- **`model/`**: pure logic, no React. `VertexId`/`EdgeId` are built from **sorted** member coords, so a corner or edge has one id from any hex. Before the first recorded turn, `withBoard` deals starting resources when the draft completes and adjusts them on later edits only for hands that still match the old grant with no unknown cards. A qualifying incumbent keeps a tied award. `turn.ts` has one pure function per in-game action. Ledger corrections between actions share one log line (`turn.correction`), and the store folds their undo steps into one when a commit not marked `correction` closes the run. `Game.turn.playerId` is whose turn it is and whom recorded actions are for. `board.mePlayerId` means only "the player whose cards are known exactly". A rival's hand is a lower bound per resource plus `handUnknown`. The typed `devHand` is dropped whenever it would exceed the public dev card count.
- **`engine/`**: no React and no TypeScript ranking logic. `setupRoad.ts` is the one engine call outside a worker, and the analysis never runs during render. `engine/advice/wasm.ts` is the one loader for `engine.wasm`. The analysis accepts every board `validateBoard` accepts, including ones the adviser refuses. Draft inference exists in both languages: change `infer_draft_state` (`analysis.rs`) and `draft.ts` together (`draftParity.test.ts` checks them). `analysisPerf.test.ts` bounds the two worst six-seat rankings, so do not add work per rollout scan casually. A fast path in a scan must return the reference path's bits (debug and test builds assert it). The `recap` decision may differ between native and wasm, so it has no parity row. A test that needs a real ranking uses `src/engine/__tests__/analyzeWasm.ts`.
- **`parser/`**: offline screenshot to `Game`. `parseScreenshot` tries Colonist.io first (it rejects images without Colonist's sea blue) and falls through to Settled, whose error stands if both fail. Settled's palette check cannot be the switch, since it accepts some Colonist screens. Parsing emits `ParseIssue[]` rather than throwing. Coverage is in [`.claude/specs/colonist/plan.md`](.claude/specs/colonist/plan.md). Settled pills fingerprint profile photos into `Game.avatars` (see [`.claude/specs/player-identity/plan.md`](.claude/specs/player-identity/plan.md)).
- **`ui/`**: `store.ts` holds the tabs, each with whole-`Game` undo stacks. Board edits dispatch `commit` (wrapped by `withBoard`), stat edits `commit-game`. Above 760px `App` mounts the desktop `Workspace`, at or below it `phone/PhoneShell`. Read [`.claude/specs/desktop/spec.md`](.claude/specs/desktop/spec.md) and [`.claude/specs/mobile/spec.md`](.claude/specs/mobile/spec.md) before touching `src/ui/phone/`, a promoted base rule or the `max-width: 760px` arm of `editor.css`. They hold every interaction rule. The two trees share components and hooks rather than forking. The Best picks step buttons (`useDraftSteps`) keep their forward list outside the store's undo stacks. While the store's `pick` is set, `BoardCanvas` routes clicks to it instead of the active tool. One home each: `useBoardActions` for randomize, clear and layout, `UndoRedoButtons` for undo and redo, `glyphs.tsx` for icons (one flat family on a 20-unit grid, except the board, the brand mark and the dice pips). An import dialog mounts outside the analysis panel or Maps popover that opens it, so it outlives them. `mergeScreenshot` never lets a value the screenshot did not read overwrite a saved one. Modals go through `ModalDialog` (native `<dialog>`), so never hand-roll a focus trap. `ContextMenu` is a native popover anchored in CSS.
- **`persistence/`**: corrupt blobs are kept under `*.corrupt` keys, never discarded. A quota failure clears the analysis cache and retries once before offering to clean up old closed games. Boards autosave into the library (`ui/libraryAutosave.ts`, 500ms debounce), so there is no save button, dirty marker or close prompt. `isFreshGame` is the one rule for "nothing beyond a fresh board", shared by autosave and backup. Beyond `MAX_MAPS` the least recently touched map is evicted, and the autosave closes any tab linked to it so it cannot re-save past the cap. Restore validates every entry before one write, never overwrites, and checks the cap after the merge. The people list and automatic board titles follow the player identity plan.
- **OTA (iOS only)**: web bundle updates through `@capgo/capacitor-updater` in manual mode (`capacitor.config.ts`, every Capgo URL blank). `src/main.tsx` reaches `src/native/` only through the native-mode dynamic import, so the website carries none of it. A bundle applies only at cold start. `StoreProvider`'s first mount calls `notifyAppReady()`: a bundle that misses it within 10 s is rolled back and never downloaded again on that store build. `tools/ota/publish.mjs` sets `minNativeBuild` from the latest run of `store/ios/*` tags whose native fingerprint (`ios/App/`, `capacitor.config.ts`, `ota/keys/bundle.pub`, `ota/native-epoch`, plugin lockfile versions) matches HEAD. With no match, no phone downloads it and every phone shows the update link until a matching store build is tagged. Bump `ota/native-epoch` when a change would break older bundles on the same native build (for example a stored format they cannot read), which forces a store build.
- **`simulator/`**: separate Rust workspace that self-plays games to measure placements, and whose engine crate the app runs. `npm test` reaches it only through the committed wasm and `simulator/fixtures/`. Never hand-edit `simulator/topology/*.json`. Change the placement scorer (`placement/app_formula.rs`), the analysis or a shipped weight and you must regenerate `simulator/fixtures/analysis-parity.json` (`cargo test --release -p unsettled-engine --test analysis_parity regenerate -- --ignored`) and re-verify its diff by hand. `wasmAnalysisParity.test.ts` holds the wasm to it exactly outside `LAST_BIT_CASES` (why, in [`contracts.md`](.claude/specs/simulator/contracts.md)). The adviser bridge (`crates/engine/src/advice.rs`) only explains scores, never changes one. Change a scorer, a policy or the rules and regenerate `simulator/fixtures/bench-hashes.json` ("Speed suite" in [`simulator/README.md`](simulator/README.md)). Spec: [`.claude/specs/simulator/spec.md`](.claude/specs/simulator/spec.md).

## Conventions

- Inter ships as `src/ui/fonts/Inter.woff2`: ASCII plus `· × − – — …`, weights 400 to 800. Any other UI character falls back to the system font, so re-cut the file when adding one: `fonttools varLib.instancer InterVariable.ttf opsz=14 wght=400:800`, then `pyftsubset --unicodes=... --layout-features=kern,tnum --name-IDs=0,1,2,3,4,5,6,13,14 --flavor=woff2`.
- UI copy capitalizes the first letter after ` · ` (`Red · Not rolled yet`), and a comma continues in lowercase. Every label starts with a capital, except a word after an inline glyph (Best picks' `then` / `or`).
- CI (`notify-site.yml`, workflow "Check and deploy") runs the app gates, e2e and Rust tests in both profiles. The Rust jobs run only when a path in its `changes` filter moved, so a file outside `simulator/` that a Rust test starts reading joins that filter. The site publishes the newest commit with a green push run on main. Never rename that file or workflow: the site's `jekyll.yml` and `dispatch-site.yml` find it by both.
- Full-page Chromium screenshots briefly resize to 1x1 and can mount the other responsive tree. Use viewport screenshots when asserting selection or open-menu state.
- Simulator changes run `cargo test` in BOTH profiles from `simulator/`. Never let `HashMap` iteration or float accumulation order reach an output (why, in [`contracts.md`](.claude/specs/simulator/contracts.md)).
- Simulator seed domains are spend-once. Never run a command carrying a spent one. Fully spent: `tuning`, `eval`, `gate`, `tuning2`, `eval2`, `gate2`, `tuning3`, `eval3`, `gate3` (these generations ignore seat count, so a domain is held out per layout). Later generations fold the seat count into the seed and are spent per seat count: `tuning4` and `gate4` at two to six seats, `eval4` at six only, `gate5` (`0x6a75_5eed_2026_1012`) at four and six, `tuning5` and `tuning6` at three to six, `eval5` and `gate6` at five only. Mint a new generation whenever a phase needs one, without asking. Ledger and phase order in [`programme.md`](.claude/specs/simulator/programme.md). `perf` (from `PERF_SEED`) is for timing and memory only, never evidence, never spent.
- A draft-aware placement arm is `app_formula_draft:<hero weights>@<opponent weights>`, with the opponent pinned to the field's weights so an A/B moves the hero alone.
- Every `sp2` through `sp6` weights arm perturbs `simulator/placement/sp6-pre-adoption-weights.json`, not the live defaults. Every `sc_*` arm perturbs the live `default-weights.json`. Anchor a new arm to the vector its own run is against, and say which in its pin test.
- Placement weights are chosen by roster size (`seat-weights/seats-<n>.json` for two to six players, else `default-weights.json`), and at five seats also by draft slot and terrain through `seat-strategies/seats-5.json`. Explicit `options.weights` bypasses selection. These JSON files are the source of truth and are edited by hand. Move a seat count's vector only with its `SEAT_ADOPTIONS` row in `params_file.rs`. What each seat count ships, in [`seat-count-programme.md`](.claude/specs/simulator/seat-count-programme.md).
- Parser correctness is guarded by the four `fixtures/settled-*.png` snapshots and their expected JSON in `src/parser/__tests__/expected/`. Regenerated expected output must be re-verified by hand. Colonist screenshots live only in the ignored `fixtures/colonist.local/` (its terms require credit on published screenshots), so CI skips `colonist.test.ts` and `colonistDamage.test.ts` and a parser change is checked on a machine that has them. Copy the folder into a new worktree with `cp -c -R`. `expected/board-draft-empty.json` has no screenshot but stays as the board other tests load.
- A cross-window sync test (`ui/workspaceSync.ts`) is worthless until shown to fail against the code it was written for. A pace under the 500ms autosave debounce coalesces into one write, and a second window that is only open never answers mid-sequence, so both make a green run meaningless.
- `.claude/worktrees` holds full repo copies, which vitest excludes.
- Change anything under `simulator/crates/engine/src`, `simulator/crates/engine/Cargo.toml`, `simulator/crates/wasm`, `simulator/topology`, `simulator/placement/default-weights.json`, `simulator/placement/seat-weights`, `simulator/Cargo.toml` or `Cargo.lock`, and you must run `simulator/tools/build-wasm.sh` and commit the new `engine.wasm` and hash, or CI fails. A comment-only edit still moves the hash. If Best picks output changed, regenerate the analysis fixture (`simulator/` above). If advice output changed, regenerate `simulator/fixtures/advice-parity.json` (`cargo test -p unsettled-engine --test advice_parity -- --ignored regenerate`) and re-verify it, since `wasmParity.test.ts` is the bit-identity gate for scores. Then regenerate `simulator/fixtures/bench-hashes.json`.
- The adviser never recommends a super city, treats a rival's dev cards as unplayed knights, and ignores the observer's cards of unknown type (the panel notes the last two when they apply). The engine refuses boards the app only warns about: `adviceBlockers` in `ui/bestMoves.ts` lists what to finish, and the panel asks for no advice until it is empty. No boons or curses hook.
